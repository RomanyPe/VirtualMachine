# Виртуальная машина и компилятор с IDE (ASM_gen)

Полнофункциональный эмулятор 64‑разрядного процессора, собственный ассемблер, C‑подобный компилятор MiniC и визуальная среда разработки на WPF.  
Проект разделён на четыре независимых слоя. Каждый слой — отдельная библиотека, которую можно использовать автономно.

- **Kernel** – ядро эмуляции: 64 битный процессор (32 регистра, ~40 инструкций), оперативная память, шина портов ввода‑вывода.
- **Compiller** – ассемблер, дизассемблер, компилятор языка MiniC в байт‑код виртуальной машины.
- **VMApplication** – средний API для управления устройствами, компиляцией и симуляцией.
- **ASM_gen** – WPF‑приложение, минималистичная IDE с редактором, подсветкой ошибок, пошаговой отладкой и дампом памяти.

> **.NET 10**

## Общая архитектура
```
┌──────────────────────────────────────────┐
│ ASM_gen (WPF UI) │ ← визуальная IDE
└────────────────┬─────────────────────────┘
│ использует только VMApplication
┌────────────────▼─────────────────────────┐
│ VMApplication (Средний API) │ ← VMHost, DeviceData, контексты запуска
└────────────────┬─────────────────────────┘
│ использует Compiller и Kernel
┌────────────────▼─────────────────────────┐
│ Compiller (Компилятор/Ассемблер) │ ← MiniC → AST → ASM, ASM → байт‑код
└────────────────┬─────────────────────────┘
│ использует Kernel (OpCode, MemoryBus)
┌────────────────▼─────────────────────────┐
│ Kernel (Ядро виртуальной машины) │ ← процессор, память, порты, BIOS
└──────────────────────────────────────────┘
```


**Зависимости проектов:**  
`Compiller` ссылается на `Kernel`.  
`VMApplication` ссылается на `Compiller` и `Kernel`.  
`ASM_gen` ссылается **только** на `VMApplication` и не обращается к низкоуровневым API напрямую.

## Kernel (ядро эмуляции)

Библиотека классов, реализующая виртуальную машину «на кристалле».

### Процессор
- **64‑разрядный**, **32 регистра** (r0…r22, специальные: rIP, rSP, rHP, rFL, rCD, rCL и др.).
- **Система команд** (`OpCode`):  
  - Арифметика: ADD, SUB, MULT\_INT, DIV, INC, DEC, SHR  
  - Логика: AND, OR, XOR, NOT  
  - Память: LOAD, STORE, LOAD\_IND, STORE\_IND (с размерами S8..S64)  
  - Управление потоком: JMP, JZ, JNZ, JG, JL, CALL, RET  
  - Стек: PUSH, POP  
  - Ввод‑вывод: IN, OUT, PRINT, PRINT\_INT  
  - Системные: NOP, HALT, ALLOC (управление кучей)  
  - Прерывания: INT, IRET  
- **Формат инструкции** (32 бита):  
  `[opcode (8)] [reg1 (5)] [reg2 (5)] [size (2)] [reserved (12)]`  
  Инструкции с 64‑битным операндом выравниваются по 8 байт.

### Шина памяти (`MemoryBus`)
- Массив `byte[]`, размер задаётся через `RamSize` (от 128 Б до 128 МБ).
- Чтение/запись с контролем выравнивания и границ.
- BIOS-область — отдельный массив, проецируемый в верхние адреса ОЗУ.

### Шина портов (`PortBus`)
- Адресное пространство поделено на секторы — каждое устройство занимает фиксированное количество портов.
- Позволяет объединять несколько виртуальных машин в одну сеть.

### Устройство (`Device`)
- Объединяет процессор, ОЗУ и шину портов.
- Загрузка программы (`LoadProgram`, `TryLoadProgramFast`).
- Пошаговое выполнение (`NextStepProcessor`), запуск в отдельном потоке (`LaunchDevice`) с настраиваемой задержкой и отладкой.

## Compiller (компилятор и ассемблер)

Библиотека, превращающая исходный код на MiniC или ассемблере в байт‑код для Kernel.

### Ассемблер
- `Assembler` – потоковая запись инструкций с метками и автовыравниванием.
- `AssemblerParser` – парсер текстового ассемблера (мнемоники, метки, комментарии).
- `InstructionEncoder` – статические методы кодирования инструкций.
- `Disassembler` – обратное преобразование байт‑кода в читаемый листинг.

### MiniC компилятор
- **Лексер** и **парсер** – строят AST.
- Поддерживаются: функции, переменные, массивы, указатели, `if`/`else`, `while`, `for`, `return`, встроенный `asm { ... }`, `new тип[размер]`, `#include`.
- **Генератор кода** (`FunctionGenerator`, `ExpressionGenerator`, `StatementGenerator`) — преобразует AST в инструкции ассемблера.

## VMApplication (средний API)

Библиотека для удобной работы из UI, скрывающая низкоуровневые детали.

- `VMHost` – главная точка входа: управление проектом, компиляция, устройства.
- `DeviceData` – обёртка над `Device`: загрузка программы, остановка, дамп памяти.
- `LaunchModeDevice`, `DeviceStepMode` – контексты запуска (пошаговый / в потоке с колбэками).
- `ProjectBuilder` – компиляция исходников проекта в байт‑код с учётом `#include` и внешних функций.
- Интерфейсы `IProjectService`, `IFileService`, `IEditorService`, `IOutputView` для интеграции с UI.

## ASM_gen (WPF IDE)

Графическое приложение, использующее только `VMApplication`.

- **Главное окно** – выбор проекта или создание нового.
- **Редактор кода** – AvalonEdit с подсветкой синтаксиса MiniC и ASM.
- **Анализатор ошибок** – в реальном времени подсвечивает строки с ошибками после каждого изменения текста.
- **Менеджер устройств** – список виртуальных машин, просмотр памяти, загрузка .bin‑файлов.
- **Окно памяти** – визуализация ОЗУ с обновлением только видимых строк.
- **Вывод** – RichTextBox с цветным логированием (`WpfOutputView`).

## Библиотека std.vma и явные внешние вызовы

В проекте **нет неявных вызовов или скрытых присваиваний**. Все функции, которые не написаны самим разработчиком, 
находятся во внешних библиотеках (например, `std.vma`). Чтобы ими воспользоваться, необходимо:

1. Подключить библиотеку директивой `#include "std.vma"`.
2. Явно объявить прототипы используемых функций с ключевым словом `extern`.
3. Вызвать эти функции в коде.

Это полностью прозрачный механизм: компилятор не вставляет никакого скрытого кода и не выполняет неявных действий.

### Содержимое std.vma
Стандартная библиотека реализует базовые системные вызовы через механизм прерываний.  
Файл std.vma и прочие готовые библиотеки доступны в директории ```include```


Все функции библиотеки (print_int, exit и т.д.) являются обычными подпрограммами, которые разработчик обязан вызвать явно. 
Никакие действия (вывод на экран, завершение работы) не происходят сами по себе.
## Пример использования

```cpp
#include "std.vma"

extern void init_vectors();
extern void print_int(int value);
extern void exit();

int main() {
    init_vectors();       // явно инициализируем таблицу прерываний
    print_int(12345);     // явно вызываем печать числа
    exit();               // явно завершаем программу
    return 0;             // эта строка не выполнится из-за exit()
}
```

Компиляция выдаст следующий байт‑код:
```asm
CALL func_init_vectors
LDI r0, 12345
CALL func_print_int
CALL func_exit
```

Никаких неявных вставок не производится — всё находится под контролем разработчика.

## Внутреннее устройство MiniC

### Регистры и память
- 21 регистра общего назначения (r0…r21).
- rSP – указатель стека (растёт вниз).
- rHP – указатель кучи (растёт вверх).
- rIP – instruction pointer.
- rFL – флаги (Zero, Negative).
- а также прочие системные регистры
#### Соглашение о вызовах:

- Параметры передаются через псевдо глобальные переменные ```__param_<func>_<name>```.
- Возврат значения — через регистр r0.
- Локальные переменные по возможности размещаются в регистрах, остальные — на стеке.

#### Компиляция выражений

Результат выражения всегда остаётся в r0.
Пример ```a = b + c``` транслируется в:

```asm
LOAD.S32 r0, [b]    // или LDI, если константа
MOV r1, r0
LOAD.S32 r0, [c]
ADD r1, r0
STORE.S32 [a], r1
```

#### Указатели и динамическая память
- ```&``` — взятие адреса переменной в r0.

- ```*``` — косвенная загрузка через LOAD_IND.

- ```new тип[N]``` — вызывает ALLOC (умножает размер элемента на N и увеличивает rHP).

#### Встроенный ассемблер
Блок ```asm { ... }``` вставляется напрямую в выходной поток. Регистры, изменённые внутри asm, не отслеживаются компилятором — ответственность программиста.


## Примеры кода MiniC с пояснениями
Ниже несколько проверенных сценариев (код и результат выполнения на эмуляторе).
Полный список тестов — в файле ```Tests.md```.

### 1. Динамическая память и вывод числа
```cpp
#include "std.vma"
extern void init_vectors();
extern void print_int(int value);

int main(){
    init_vectors();
    int* arr = new int[10];
    arr[0] = 5;
    arr[1] = 10;
    print_int(arr[0]);   // 5
    return 0;
}
```

2. Встроенный asm
```cpp
int main() {
    int x = 10;
    asm {
        LDI r0, 5
        MOV r1, r0
    }
    print_int(x);   // 10 (asm не меняет переменные C)
    return 0;
}
```

3. Работа с портами ввода‑вывода
```cpp
#include "std.vma"
extern void init_vectors();
extern void out_port(int port, int value);
extern int  in_port(int port);
extern void print_int(int x);
extern void exit();

int main() {
    init_vectors();
    out_port(2, 0x99);
    int val = in_port(2);
    print_int(val);   // выведет то, что вернуло устройство на порту 2
    exit();
    return 0;
}
```
Перед запуском необходимо зарегистрировать устройство на соответствующем секторе шины портов.
